## 前后端传参方式不匹配：
浅层分析：后端要URL参数（projectId=xx），前端确保参数放在JSON里，导致后端退市projectId参数不存在；
深层分析：后端要扁平的JSON（{projectId:xxx, nodeId:xxx}）,前端却包了一层params导致JSON解析失败
### 2. 路由参数名不匹配：
路由配置里参数占位符是“id，前端代码却去，拿router.params.projectId，导致参数为空，按钮无法跳转

### 前后端传参的两种方式：
URL参数：后端通过@RequestParam注解接收  前端传参位置：axios 的`params`配置
JSON Body：后端通过@RequestBody注解接收  前端传参位置：axios.post 的第二个参数
-  浅层分析的错误例子：
```ts
// 前端API封装（错误：把参数放JSON Body，后端要URL参数）
triggerShallowAnalysis(params: { projectId: string }): Promise<any> {
  return http.post('/analysis/triggerShallow', { params }); // 错：Body传参
}
```
- 正确修改：
```ts
// 前端API封装（正确：参数放params，Body置空）
triggerShallowAnalysis(params: { projectId: string }): Promise<any> {
  return http.post('/analysis/triggerShallow', {}, {
    params: params // 对：URL参数（?projectId=xxx）
  });
}
```
- 深层分析的错误例子
```ts
// 前端API封装（错误1：嵌套params；错误2：字段名projectId，后端要project）
triggerDeepAnalysis(params: { projectId: string; nodeId: string }): Promise<any> {
  return http.post('/analysis/triggerDeep', { params }); // 错：{params:{projectId:xxx}}
}
```

### 知识点：
#### JSON 解析关键规则

- 后端用`@RequestBody Map<String, String>`接收时，JSON 必须是**扁平结构**（`{key: "value"}`），不能嵌套对象（`{params: {key: "value"}}`），否则解析失败。
