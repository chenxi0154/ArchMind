## 什么是依赖注入？

比如你有一个登录服务：

`@Service public class LoginService { private final UserRepository userRepository; public LoginService(UserRepository userRepository) { this.userRepository = userRepository; } }`

这里的 LoginService 依赖 UserRepository。

以前可能需要自己写：

`UserRepository userRepository = new UserRepository(); LoginService loginService = new LoginService(userRepository);`

而 Spring 的方式是：

`Spring 创建 UserRepository ↓ Spring 创建 LoginService ↓ 自动把 UserRepository 塞进去`

这就是 **依赖注入 DI**。

## 依赖注入的核心思想：
**一个类需要某个对象**，但是自己不负责创建这个对象，而是由外部把它提供进来。

---

## 为什么认证功能会出现依赖注入问题？

因为认证通常会涉及遗传对象：

`Controller ↓ AuthenticationManager ↓ AuthenticationProvider ↓ UserDetailsService ↓ UserRepository ↓ 数据库`

只要其中某一个对象：

- 没有注册成 Bean
- 注册了多个 Bean，Spring 不知道选哪个
- Bean 创建失败
- 手动 new 了对象
- 配置类没有被扫描

都可能导致认证相关功能出问题。

## 依赖注入方式

Spring 提供三种注入方式，核心区别在于：**依赖从哪条路被塞进对象里**。

### 构造器注入（官方推荐）

依赖通过**构造函数**传入，对象创建的那一刻就必须拿到所有依赖。

```java
@Service
public class LoginService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    // Spring 自动找到这两个 Bean，通过构造器传入
    public LoginService(UserRepository userRepository, PasswordEncoder passwordEncoder) {
        this.userRepository = userRepository;
        this.passwordEncoder = passwordEncoder;
    }
}
```

- 只有一个构造器时，`@Autowired` 可以省略（Spring 4.3+ 自动识别）。
- 配合 Lombok 可以更简洁：

```java
@Service
@RequiredArgsConstructor
public class LoginService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
}
```

**特点：**
- 依赖可以是 `final`，不可变、线程安全
- 创建时依赖必须齐全，**少注入一个直接启动报错**（fail-fast）
- 单元测试最方便：直接 `new LoginService(mockRepo, mockEncoder)` 传 mock
- 缺点：依赖太多时构造器参数会很长（通常说明这个类该拆了）

### setter 注入

依赖通过 **setter 方法**传入，对象可以先创建，依赖之后再塞。

```java
@Service
public class LoginService {

    private UserRepository userRepository;

    @Autowired  // 必须有，Spring 才会调用这个 setter
    public void setUserRepository(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}
```

**特点：**
- 依赖**可选**：没注入时对象也能先存在
- 可以在运行时**重新注入 / 替换**依赖
- 不能用 `final`，依赖可能被中途改动
- 必需依赖可能被漏注入，直到真正使用才 NPE（fail-late）

### 字段注入

依赖通过**反射直接塞进字段**，代码最省。

```java
@Service
public class LoginService {

    @Autowired
    private UserRepository userRepository;

    @Autowired
    private PasswordEncoder passwordEncoder;
}
```

**特点：**
- 代码最短，看着最省事
- 依赖被**隐藏**在字段里，外部看不出这个类到底需要什么
- 不能 `final`，无法保证不可变
- 单元测试麻烦：必须依赖 Spring 容器或反射，无法 `new` 出来传 mock
- IDEA 会给出 "Field injection is not recommended" 警告

## 场景区分（该用哪种）

| 场景 | 推荐方式 | 原因 |
| --- | --- | --- |
| 必需依赖（没它类不能工作） | 构造器注入 | 启动即校验，少注入直接报错 |
| 想写单元测试 | 构造器注入 | 能 `new` 出来手动传 mock |
| 依赖可选 / 有默认值 | setter 注入 | 没注入也能正常工作 |
| 运行时需要换实现 | setter 注入 | 可以重新 setter |
| 快速原型 / 临时代码 | 字段注入（仅限此场景） | 快，但别进正式代码 |

**结合认证场景举例：**

- `UserRepository`、`PasswordEncoder`、`UserDetailsService` 都是**认证必需**的依赖 → **构造器注入**
- 某些可选的通知、审计组件（没有也能登录）→ **setter 注入**
- 网上抄的、图省事的旧代码 → 字段注入，能改就改成构造器注入

**关于循环依赖：** 构造器注入遇到循环依赖会启动报错；字段 / setter 注入 Spring 能靠代理兜底。但正确做法是**重构消除循环依赖**，而不是靠换注入方式绕过。

> 结论：**默认用构造器注入**；只有依赖真的「可有可无」时才用 setter；字段注入能不用就不用。

## 构造器

构造器是对象创建时执行的特殊方法。

```java
public UserService(UserRepository userRepository) { this.userRepository = userRepository; }
```

**Spring 依赖注入，就是 Spring 负责创建和管理对象，并在创建一个对象时，把它所依赖的其他对象通过构造器等方式传进去，让这个对象持有这些依赖的引用，而不需要自己 new。**


```

          │
          ↓
Lombok生成构造器
          │
          ↓
public AuthServiceImpl(
    UserService userService,
    JwtUtil jwtUtil,
    RedisUtil redisUtil,
    PasswordEncoder passwordEncoder
)
          │
          ↓
       编译完成
          │
════════════════════════════════════
          ↓
                 【运行阶段】

Spring Boot启动
          │
          ↓
扫描 @Service
          │
          ↓
发现 AuthServiceImpl
          │
          ↓
发现它有构造器
          │
          ↓
发现构造器需要：
          │
     ┌────┼─────┬─────────────┐
     ↓    ↓     ↓             ↓
 UserService JwtUtil RedisUtil PasswordEncoder
     │    │     │             │

                ↓
        从 Spring 容器中找到
                ↓
          调用构造器
                ↓
     new AuthServiceImpl(...)

     this.redisUtil = ...

            创建完成
```
