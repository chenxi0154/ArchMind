JWT配置没有绑定的本质是配置文件里虽然写了值，但是Spring不会自动把他们填进任意一个Java对象的字段中。

当前配置文件定义了四个jwt参数：
- 签名密钥 secret
- access token 过期时间
- refresh token 过期时间
- 签发者 issuer
而jwt工具类中也声明了四个对应字段，但是两者只是名字相同，还没有建立Spring所认识的绑定关系。因此运行时这些字段仍保持Java默认值：
- 字符串字段：null
- 数字字段为：0；

---
## 为什么Spring不会自动注入？
SpringBoot的application.yml是一个配置源。应用启动时，它会读取其中的键值，形成类似一下的配置项：
```
jwt.secret
jwt.access-token-expire
jwt.refresh-token-expire
jwt.issuer
```
但是Spring要把这些配置项放到对象里，必须有一个明确的机制告诉它：
	 哪个对象需要这些配置
	 
常见的绑定机制有两类：

1. 单个配置值注入：明确指定“这个字段读取 jwt.secret”
2. 配置属性绑定：明确指定“这个对象整体对应 jwt 前缀”

当前 JwtUtil 虽然被 Spring 创建成 Bean，但它只是一个普通组件。Spring 知道要创建它，却不知道 secret 字段应当来自 jwt.secret，也不知道过期时间和 issuer 应从哪里来。

所以，“Bean 被 Spring 管理”不等于“配置会自动注入到 Bean 的任意字段”。


---

## 它会在什么时候出错

登录时系统要签发 access token 和 refresh token。签发前必须计算过期时间，例如：

当前时间 + accessTokenExpire

但 accessTokenExpire 实际是 null。一旦尝试把它转换成数字，就会抛出异常，登录无法继续。

即使假设过期时间侥幸处理过去，生成签名密钥时仍需要：

secret 的字节数组 → HMAC 密钥

但 secret 仍是 null，调用其相关方法时会空指针失败。

因此该问题不是“JWT 使用了默认值”或“安全性略有下降”，而是：

> 当前代码在实际签发或解析 JWT 时无法正常工作

## 为什么配置文件写了也没有用

可以把 application.yml 看成一个仓库，把 JwtUtil 看成一个空容器。

目前的状态是：

配置仓库里有 jwt.secret JwtUtil 容器里有 secret 字段 但两者之间没有管道

所以值一直留在配置仓库中，JwtUtil.secret 不会自行读取它。

尤其要注意：字段名称相同也不构成绑定。例如：

配置：jwt.secret 字段：private String secret;

Spring 不会通过“猜测”自动完成这一映射。自动猜测会产生歧义：项目可能有数据库密钥、第三方 API 密钥、文件加密密钥等多个 secret，Spring 无法判断应当填哪一个。

## 正确的设计原则

JWT 配置应当被视为一组完整、不可缺少的安全参数，而不是散落在工具类中的几个字符串。

一个合理的设计应满足：

- 启动时将 jwt.* 整体绑定到专用配置对象；
- JWT 工具只依赖该配置对象，不自己持有未初始化的配置字段；
- 启动阶段校验密钥是否存在、强度是否达标、过期时间是否为正数；1
- 生产环境从环境变量、密钥管理服务或部署平台密文配置读取密钥；
- 配置缺失或无效时直接让应用启动失败，而不是等首次登录才报空指针。

这样能把故障从“用户登录时报 500”提前到“部署时立即发现配置错误”。

## JWT配置里的密码作用
注意一部分是JWT做水闸前面，用来保证令牌没有被伪造和篡改
登录成功后，服务端会生成一段JWT，里面可能包含：
- 用户ID
- 用户名
- token
- 签发时间
- 过期时间
- 签发者

然后服务端使用 jwt.secret 对这些内容生成签名，并把签名附到 token 后面。
