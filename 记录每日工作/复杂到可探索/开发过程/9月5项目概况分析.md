## 一、本次做了什么

P0 已完成（注册登录 / JWT / zip 上传 / 文件树）。本次从「先接 LLM 还是先做任务系统」的讨论收敛出一个关键认知：

> **这个项目里 LLM 不是「对话」，是「结构化分析器」。** 它的输入是 pom / README / 目录 / AST，输出是结构化 JSON 存库，全程不面向用户聊天。所以「单纯 AI 对话」先不做。

**落点顺序结论**：②项目概况 → ①任务系统 → ③AST 提取。本次实现**②项目概况**：读 pom + README → 裁剪 pom → 组 prompt → LLM 结构化输出 → 落 MySQL。**这一步不需要 Neo4j**（Neo4j 随 AST 阶段引入，已定）。

## 四、整体流程（5 步）

```
Controller.analyze(projectId)
   │ 校验项目归属（CheckProjectUtil）
   ▼
Service.projectOverview(projectId)
   ① 定位落盘根目录 + 找 pom.xml / README
   ② 裁剪 pom（保留 parent/properties/modules/dependencies）
   ③ README + 裁剪后 pom 组装中文提示词
   ④ ChatClient 调 LLM → 结构化 JSON（.entity(DTO.class)）
   ⑤ 序列化嵌套字段 → 写 project_overview（幂等覆盖）
```

### 逐步实现要点

**① 找文件（关键：file 表只有路径没有内容）**
`file` 表字段是 `file_path / file_name / hash`，**没有 content 列**，所以「找到」得到的是磁盘路径，再走现成的 `FileContentService.readTextContent(Path)` 读正文。
- 根目录定位：`project_source.content` 存了解压根目录的**绝对路径**，`project_source.fileId` 是根目录文件 id
- pom：优先根目录下 `pom.xml`，退化到该项目任意一个
- README：根目录下 `fileName.toLowerCase().startsWith("readme")`，大小写不敏感；**缺失降级为 null，不中断**

**② 裁剪 pom**
```java
for (String tag : List.of("parent", "properties", "modules", "dependencies")) {
    Pattern p = Pattern.compile("<" + tag + "\\b[^>]*>.*?</" + tag + ">", Pattern.DOTALL);
    // 保留这四段，其余 build/plugin/仓库配置等噪声丢弃
}
```
> `modules` 必须保留——多模块项目根 pom 的 dependencies 往往很空，技术栈在子模块里。

**③ 提示词**
中文约束：`projectType` 枚举（后端服务/前端应用/全栈/库/工具/其他）、字段含义、「只输出 JSON、不要解释或代码块标记」。

**④ 调 LLM（Spring AI 2.0 用法）**
```java
ChatClient chatClient = ChatClient.create(chatModel);
ProjectOverviewResponse resp = chatClient.prompt(prompt)
        .call()
        .entity(ProjectOverviewResponse.class);
```

**⑤ 写库（幂等）**
嵌套结构（techStack/architecture/modules）用 Jackson `writeValueAsString` 序列化成 JSON 列；`project_overview` 1:1 一个项目一条 → **先 `delete(projectId)` 再 `insert`**，重分析覆盖。同时存 `raw_response`（LLM 原文）供调试。

## 五、数据表

```sql
CREATE TABLE IF NOT EXISTS "project_overview" (
    id                INTEGER PRIMARY KEY,
    project_id        INTEGER NOT NULL,
    project_type      VARCHAR(64),
    summary           VARCHAR(512),
    description       TEXT,
    tech_stack_json   TEXT,
    architecture_json TEXT,
    modules_json      TEXT,
    raw_response      TEXT,
    model             VARCHAR(64),
    create_time       TEXT
);
```

**关键设计：能查询/筛选的做列（project_type/summary），结构不定的做 JSON 列。** 三个 `*_json` 里存的不是字符串，是 LLM 返回的嵌套 JSON。

## 六、LLM 输出 DTO 与存储实体分离

LLM 返回 JSON 是**嵌套**的，DB 存的是**扁平列 + JSON 串**，所以要两个类，别让实体直接承接 LLM 输出：

```java
// ProjectOverviewResponse —— LLM 契约 / 前端返回（嵌套）
class ProjectOverviewResponse {
    String projectType;  String summary;  String description;
    List<TechStackItem> techStack;        // name/category/version/role
    Architecture architecture;            // style/layers/description
    List<ModuleItem> modules;             // name/responsibility/keyFiles
}

// ProjectOverview —— 存储实体（扁平 + JSON 列）
class ProjectOverview {
    Long id; Long projectId; String projectType; String summary;
    String description;
    String techStackJson; String architectureJson; String modulesJson;
    String rawResponse; String model; LocalDateTime createTime;
}
```
