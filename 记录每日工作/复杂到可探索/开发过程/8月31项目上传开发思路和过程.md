## Controller
接收参数，调用方法，return 结果；
**注解目的**：
@RestController：
给类的身份标签，告诉Spring容器，这个类是用来处理HTTP请求的后端接口
- 它是`@Controller` + `@ResponseBody`的组合注解，专门用来写 RESTful 风格的接口。
- 必须是加在controller类上，Spring才会把这类接口当成接口处理器来管理

@RequestMapping：
给类和方法贴的路由总开关，用于绑定请求的URL路径，请求方式，请求头等，是最通用的路由注解，统一接口前缀。
- 可以加在类上，也可以加在方法上
- 致辞配置method属性指定请求方式，也支持不指定，匹配所有请求方式
- 是请求映射注解的父注解

@RequiredArgsConstructor
生成构造器，用于依赖注入
- Spring 的 Controller、Service、Component、Filter、Handler；
- 类依赖其他 Bean；
- 希望使用构造器注入；
- 依赖创建后不应变更，因此字段通常写 final。

```java
@RestController
@RequestMapping("/projects")
@RequiredArgsConstructor
public class ProjectSourceController {

    private final ProjectUploadService projectUploadService;

    @PostMapping("/{projectId}/upload")
    public Result<?> upload(
            @PathVariable Long projectId,
            @RequestParam("file") MultipartFile file) {

        projectUploadService.upload(projectId, file);

        return Result.success();
    }
}

```

**补充文件解压的代码实现**：

### Files是java.nio.file.Files提供的工具方法
	Files.newInputStream作用是根据Path去操作系统中打开这个文件，返回一个能够从头顺序读取字节的InputStream。
	重点：
- 它只是**「打开」文件，不是「读完」文件**。调用瞬间建立到文件的连接（操作系统层面的文件句柄 / 通道），但文件内容不会一次性进内存，字节是后面每次 `read()` 时按需取的，所以大文件也不会撑爆内存。
- 默认以**只读**方式打开；如果路径指向的文件不存在，会抛 `NoSuchFileException`（属于 `IOException`，正好被外层 catch 住）。
- 它是 NIO（`java.nio.file`）那一套写法，作用等同于老式的 `new FileInputStream(zipFile.toFile())`，区别是它直接接收 `Path`、异常类型更清晰。
- 返回的流**必须关闭**，否则文件句柄一直被占 —— 这就是为什么要写在 `try(...)` 里。

### InputStream是什么，用它能是实现什么？
InputStream是Java中所有字节输入流的抽象父类，它只规定一件事：能从某个来源以巩固读出字节，并定义统一方法。
	真正干活的是它的各个子类，数据来源不同就用不同子类：
```
|子类|字节从哪来|
|---|---|
|`FileInputStream`|磁盘文件|
|`ByteArrayInputStream`|内存里的 byte 数组|
|`Socket.getInputStream()`|网络连接|
|`ZipInputStream`|把另一个流的字节按 ZIP 格式解析|
```
